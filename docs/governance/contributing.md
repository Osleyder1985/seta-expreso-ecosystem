# Contribucion

Todo cambio relevante debe ser trazable a una Issue o necesidad documentada.

1. Identificar necesidad.
2. Analizar evidencia.
3. Crear rama.
4. Implementar el cambio minimo.
5. Ejecutar validaciones.
6. Abrir PR con trazabilidad.
7. Revisar CI.
8. Integrar.
9. Verificar en main.

Cambios de arquitectura, seguridad, dominio, gobernanza o decisiones tecnologicas deben actualizar su documentacion y usar ADR cuando corresponda.

No cerrar Issues sin evidencia, no incorporar datos personales reales en PoCs y no almacenar secretos.
